Hierarchical city generator

For my third year project I built this city generator where each part of the generation is split into a separate component defined by its own interface, creating a hierarchy of different layers of generation.

Generation

When the generate method is called on the overall generator component it will sequentially call the generation method on each of the components for each layer:

  • Road generation - Creates road path and places road meshes
  • Building generation - Allocates builidng plots and places meshes inside each plot
  • Road details generation - Scatters details such as benches and signs across the roads
  • Building details generation - Adds details to building attachment pins

Layered Approach

Each layer's component is defined by an interface through which all communication with other layers takes place, through the inputs and outputs.

This allows for different implementations to be swapped out in place of a certain component while allowing all other layers to continue to function as expected.

Space Collonisation Algorithm

To generate the path for road meshes to be instanced on I make use of the space collonisation algorithm. This algorithm scatters attraction points across a given area, which road points then grow towards iteratively to create a natural shaped road design.

Minimum Cycle Basis

To allocate plots for buildings I make use of a Minimum Cycle Basis algorithm to detect the smallest cycles in the graph of road nodes - being the closed loops where buildings can be placed. These cycles are then inset away from the roads and then subdivided until they reach a requried approximate area range for building meshes to be placed in.

Snappable Meshes

Building details are added using an iterative algorithm which searches for connection points placed in the world (on buildings) and attempts to align the points on details with these connectors, if placement rules allow them to be connected. Placement rules specify that if two connection points have the same pin count and their pin colours match a matrix of compatible colours then they are allowed to connect, allowing different details to be placed in different areas or for details to chain following one way relationships due to the non-symetric nature of the matrix.
